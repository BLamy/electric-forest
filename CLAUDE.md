# electric-forest

A GitHub clone built on **durable streams instead of git**: every repo is a set of
append-only streams (a main stream per project, branch streams forked from it), files live
on stream-fs, changes sync live to every user of a branch, and each project carries a
`.eforest/` directory that stores not the history of file changes but **the future of what
we are building and the proof of what we have built** — including the builder/critic loop
that builds the project itself.

**Read `AGENTS.md` before doing any work.** It is the operating manual: builder protocol,
critic charter, evidence doctrine, and the gauntlet every task passes through. This repo
dogfoods its own product: our tasks live in `.eforest/tasks/`, one **folder per task**.

- `ROADMAP.md` — where we're going (epics E0–E7, capability layers, named milestones).
- `.eforest/tasks/QUEUE.md` — what's next (regenerate with `python3 tools/build_queue.py`
  after any frontmatter change; never edit QUEUE.md by hand).
- `.eforest/tasks/README.md` — task folder anatomy and queue rules.
- `.eforest/loop.md` — the loop definition: the builder and critic agents, and the project
  states (`building` / `complete` / `paused` / `invalid_loop`).
- `.claude/workflows/` — the doctrine as runnable orchestrations (`implement-task`,
  `verify-task`, `work-queue`, `plan-epic`, `replay-triage`, `golden-sweep`,
  `roadmap-audit`).
- `tools/replay/` — browser-layer evidence (Replay recording + MCP interrogation).
- `tools/verify/` — adversarial verification entry points (cold clone, self-check, runbook).

Build gates, in ascending cost (all must pass before any claim):
`pnpm format:check && pnpm lint` → `pnpm typecheck` → `pnpm test` → `pnpm build`.

Hard rules:
- The only way to mutate stream-backed state is appending an event through the dispatch
  door — no side-channel writes, ever. State is `replay(events)`; every feature is born
  replayable and every session is a trace.
- State-equality claims are digest comparisons over canonically-encoded state (exact
  match, `cmp` semantics), not eyeballs — unless a task explicitly documents a tolerance.
- Goldens are frozen committed artifacts; a golden regenerated by the code under test at
  test time proves nothing.
- Status changes go through task frontmatter (`.eforest/tasks/*/*/readme.md`) +
  `python3 tools/build_queue.py`; only an adversarial critic sets `verified`.
- All task scratch work (throwaway scripts, probes, validation runs) goes in that task's
  own folder under `work/` (gitignored); durable evidence artifacts go in its `evidence/`
  (committed). `/tmp` is for people who don't have a task folder.
